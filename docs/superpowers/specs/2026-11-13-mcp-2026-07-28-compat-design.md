# MCP 2026-07-28 compatibility — design

Approved 2026-11-13. Source: recommendation 1 in
[docs/market-research-2026-11.md](../../market-research-2026-11.md).

## Why

The 2026-07-28 MCP spec is final and removes protocol sessions, the
`Mcp-Session-Id` header and the `initialize` handshake, with no deprecation
window. Two things here depend on what it removed:

- **Session identity.** `telemetry/instrument.py` keys a Session on the
  `mcp-session-id` header and falls back to one per-process id. Every
  2026-07-28 client on the shared HTTP server therefore collapses into a
  single session. Issue #8 makes the server-composed Session Trace the
  guaranteed floor, and it needs sessions it can tell apart.
- **The nudge channel.** The server `instructions` now arrive only in the
  `server/discover` result, which clients MAY call. Tool descriptions arrive
  with `tools/list`, which every client calls.

The live container already runs `mcp` 2.3.0 (Docker ignores `uv.lock`), while
the lock and the floor said 2.0.0.

## Goals

- Tell sessions apart for 2026-07-28 clients without asking the agent to do
  anything (issue #8: agent compliance is measurably rare).
- Record how each session id was obtained, so the close rate can be measured.
- Put the save-as-you-go guidance where every client sees it.
- Lock and floor `mcp` at the version actually running.

## Non-goals

- Detecting that a session ended, writing the Session Trace (issue #8 build).
- Rebuilding or redeploying the live container.
- An explicit session handle parameter on every tool (SEP-2567 pattern). It
  is more precise but only works when agents pass it; possible later step.

## Approaches

1. **Server-derived identity (chosen).** The server derives a Session from
   what each request already carries and splits it on an idle gap. Needs
   nothing from the agent.
2. **Explicit handle.** `memory_manifest` mints a handle, every tool accepts
   it. Precise, but adds a parameter to all tool schemas and depends on the
   agent threading it through. Deferred.
3. **Header only (today).** Breaks for every modern client.

## Design

Session id precedence for each recorded call, with `session_source`:

| Source | When | Session id |
|---|---|---|
| `header` | the request carries `mcp-session-id` (handshake-era clients) | the header value |
| `derived` | an HTTP request without that header | a server-minted id for the key below, renewed after an idle gap |
| `process` | no HTTP request at all (stdio) | the per-process id, as today |

Derived key: `(agent name, agent version, caller, project)`, where caller is
the client's remote address plus, when present, a SHA-256 fingerprint of the
bearer token (header or `?token=`). (Amended after the final review: the
server has one shared token, so the token alone would merge every machine
into one session under auth.) `CONTEXT.md` defines a Session as one agent
on one Project, which is why project is part of the key. A key idle for longer
than `BLUEOCEAN_SESSION_IDLE_SECONDS` (default 1800, matching the SDK's own
legacy-session idle expiry) gets a new id on its next call.

Constraints on the tracker: in memory, locked, bounded (LRU, 10 000 keys),
never raises into a tool call, never stores the raw token. Lost on restart,
which is correct: a restart ends every session.

Honest ceiling: two windows of the same agent version, same caller and same
project merge into one session. Only an explicit handle can split them.

Also in scope:

- New telemetry column `session_source` (one line in `_EVENT_COLUMNS`; the
  existing migration adds it to older databases).
- The Hermes bridge sends a client name, so its calls stop showing as the
  SDK default `mcp`.
- `memory_manifest` and `memory_store` descriptions carry the save-as-you-go
  trigger from issue #10 (write when something is decided that a future
  session would otherwise re-derive). The server `instructions` stay.
- `mcp>=2.3.0,<3.0.0`, lock at 2.3.0. SDK 2.2+ expires idle handshake-era
  sessions after 30 minutes with a 404; the Hermes bridge already reconnects
  once on failure, so the SDK default stays.

## Left to the builder

- Calls with no project (`memory_list_projects`) key on an empty project.
- Where client info is read on the modern path (session params or the
  request `_meta`); the test against a real 2026-07-28 client decides.
