# MCP 2026-07-28 Compatibility Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Tell sessions apart for 2026-07-28 MCP clients without asking the agent, record how each session id was obtained, and put the save-as-you-go guidance where every client sees it.

**Architecture:** A small, locked, bounded in-memory tracker (`telemetry/sessions.py`) derives a session id from what each HTTP request carries and renews it after an idle gap. `instrument.py` asks it for an id when no `mcp-session-id` header is present and stamps `session_source` on the row.

**Tech Stack:** Python 3.12, `mcp` 2.3.0 (`mcp.client.Client` with `mode="2026-07-28"` for tests), SQLite telemetry, Qdrant.

**Spec:** `docs/superpowers/specs/2026-11-13-mcp-2026-07-28-compat-design.md`

## Global Constraints

- `mcp>=2.3.0,<3.0.0`; lock resolves 2.3.0.
- `BLUEOCEAN_SESSION_IDLE_SECONDS`, default `1800`.
- Tracker bound: 10 000 keys, LRU eviction.
- `session_source` values: exactly `header`, `derived`, `process`.
- The raw bearer token is never stored or logged; only a SHA-256 fingerprint.
- Nothing in telemetry may raise into a tool call.
- Tests are standalone scripts (`uv run python -m tests.<name>`), servers on 879x ports, telemetry DB in a temp dir.

## Review Focus

- Token via `?token=` query param (Kiro) must fingerprint the same as the same token in `Authorization: Bearer`. Test in Task 2.
- A request with no client info at all (anonymous stateless) must still record, keyed on an empty agent name. Test in Task 2.
- Concurrent calls from many threads must not corrupt the tracker or raise. Test in Task 2 (unit, threads).
- An older telemetry DB without `session_source` must migrate on open. Test in Task 2.
- Eviction at the bound must not raise and must drop the least-recently-seen key. Test in Task 2 (unit, small bound).
